# معالج ISBN الذكي — v2.0 (Next.js)

تطبيق Next.js 14 (App Router + TypeScript) يستخرج بيانات وصفية للكتب من
Open Library انطلاقاً من ملف Excel يحتوي على أكواد ISBN، مع منتقي حقول،
وتصدير Excel و JSON، وتحسين كامل لمحركات البحث (SEO).

هذا مشروع v2 المبني وفق `Updating Version 2 Guide`، تحويلاً لأداة
`index.html` الأصلية (صفحة HTML ثابتة) إلى تطبيق Next.js حديث.

## المتطلبات

- Node.js ≥ 18.17
- npm

## التشغيل محلياً

```bash
npm install
cp .env.example .env.local   # عدّل NEXT_PUBLIC_SITE_URL حسب نطاقك
npm run dev
```

افتح http://localhost:3000

## الأوامر المتاحة

| الأمر            | الوصف                                                        |
|------------------|----------------------------------------------------------------|
| `npm run dev`    | تشغيل بيئة التطوير                                              |

| `npm run start`  | تشغيل نسخة الإنتاج المبنية                                      |

## النشر على Vercel

1. ارفع المشروع إلى مستودع GitHub.
2. اربطه بمشروع جديد على Vercel (يكتشف Next.js تلقائياً، لا إعدادات إضافية).
3. أضف متغيّر البيئة `NEXT_PUBLIC_SITE_URL` بقيمة نطاقك الفعلي في إعدادات
   المشروع على Vercel (Settings → Environment Variables) — يُستخدم في
   sitemap.xml و robots.txt و Open Graph و JSON-LD.
4. بعد النشر: أضف الموقع في Google Search Console وأرسل رابط `sitemap.xml`
   (راجع القسم الخاص بذلك في مستند المتطلبات الأصلي لمزيد من التفاصيل).

app/

## سلسلة المصادر المتدرجة (Fallback Chain)

منذ v2.1، لا يعتمد `/api/books` على Open Library وحدها. لكل ISBN لم يُعثر
عليه، يُحاوَل بالترتيب:

1. **Open Library — bibkeys** (`lib/openlibrary.ts`) — كما كان دائماً، دفعة واحدة/طلب.
2. **Open Library — search.json** (`lib/openlibrary.ts`) — فهرس مختلف داخل نفس المصدر، بلا تكلفة إضافية.
3. **Google Books** (`lib/googlebooks.ts`) — فقط للأكواد التي فشلت في 1+2. هذا التصميم بحد ذاته يحمي الحصة اليومية المحدودة (1000 طلب/يوم افتراضياً) لأنه لا يُستهلَك إلا على "الكتب الصعبة".
4. **Wikidata** (`lib/wikidata.ts`) — الملاذ الأخير، بلا أي حد يومي، عبر SPARQL.

المنطق كله في `lib/cascade.ts` (`resolveBookBatch`) — مفصول عمداً عن
`app/api/books/route.ts` (الذي يتولى فقط اهتمامات HTTP) ليكون قابلاً
للاختبار بمعزل عن Next.js (راجع `scripts/verify.ts`).

**حماية حصة Google Books تفاعلية لا استباقية**: عند استلام 403/429 من
Google، تتوقف بقية تلك الدفعة عن استخدامها، ويُرسِل العميل (المتصفح)
`skipGoogleBooks: true` تلقائياً في كل الدفعات اللاحقة لبقية الجلسة
(`components/IsbnProcessorApp.tsx`) — بلا حاجة لعدّاد أو قاعدة بيانات،
لأن الحالة تعيش في ذاكرة المتصفح لا الخادم (الخادم عديم الحالة كما كان).

حقل **"المصدر"** أصبح حقلاً مختاراً حقيقياً في منتقي الحقول الآن (كان
"Open Library" ثابتاً دائماً سابقاً) — يظهر أي مستوى أجاب فعلياً لكل كتاب.

**اختياري**: أضف `GOOGLE_BOOKS_API_KEY` في `.env.local` لحصة موثّقة أعلى
(راجع `.env.example`). بدونه يعمل المستوى الثالث فعلياً عبر حصة مشتركة
غير موثَّقة بدقة من جوجل (أضعف لكنه يعمل).

## قرارات تقنية مهمة (وأسبابها)

- **إصدارات التبعيات**: تم تثبيت Next.js 14.2.35 و React 18.3.1 عمداً بدل
  أحدث إصدار متاح، لضمان استقرار وسلوك معروف بثقة تامة. الترقية إلى
  Next 15/16 ممكنة مستقبلاً لكنها تغيير أكبر (انظر PROJECT_REPORT.md).
- **بدون Tailwind**: تم الإبقاء على التصميم كـ Global CSS (خيار مذكور
  صراحة في مستند المتطلبات) للحفاظ على تطابق بصري 100% مع التصميم
  الزجاجي الأصلي دون مخاطرة إعادة كتابته بـ utility classes.
- **الخطوط عبر `<link>` بدل `next/font/google`**: راجع التعليق في
  `app/layout.tsx` — قرار مقصود لضمان بناء موثوق في أي بيئة.
- **`/api/books`**: كل طلب يحمل دفعة واحدة (حتى 25 ISBN) بدون حالة
  (stateless) — تنظيم التوقيت بين الدفعات (~1 طلب/ثانية) يبقى من جانب
  المتصفح تماماً كالنسخة الأصلية (`lib/rate-limiter.ts`).
- **الكاش**: `Map` في الذاكرة فقط (`lib/cache.ts`) — بدون Redis أو قاعدة
  بيانات، تماماً كما يشترط مستند المتطلبات.

## ملاحظات ومعروفات (كن على علم بها)

- **الأيقونة**: لم يكن ملف `favicon.ico` الأصلي ضمن الملفات المرفوعة،
  فتم توليد `app/icon.svg` بديل بسيط يطابق ألوان الهوية البصرية. استبدله
  بشعارك الحقيقي متى توفر.
- **صورة Open Graph**: لم تُضَف (`openGraph.images`) تجنباً للإشارة إلى
  ملف غير موجود؛ إضافة صورة 1200×630 لاحقاً تحسين جيد اختياري.
- **حزمة `xlsx` (SheetJS)**: للنسخة المنشورة على npm ثغرات معروفة غير
  مُصلَحة (Prototype Pollution، ReDoS) — هذا معروف وموثّق من SheetJS
  أنفسهم. في هذا المشروع تُستخدَم `xlsx` من جانب المتصفح فقط (قراءة ملف
  المستخدم نفسه وتصدير النتائج) وليس أبداً على الخادم، مما يحصر الأثر في
  متصفح المستخدم نفسه فقط. لإزالة الثغرة تماماً مستقبلاً، يمكن التثبيت من
  CDN الرسمي لـ SheetJS بدل سجل npm (`https://cdn.sheetjs.com`).
- تفاصيل الاختبار الكاملة، وما أمكن التحقق منه فعلياً مقابل ما لم يكن
  ممكناً في بيئة البناء (تحديداً الاتصال الحي بـ Open Library وGoogle
  Books وWikidata)، موثّقة بالكامل في `PROJECT_REPORT.md`.
- **مصادر v2.1 الجديدة لم تُختبَر حياً بعد**: منطق `search.json`
  و`Google Books` و`Wikidata` مبني على توثيق كل مصدر (وشكل استجابته
  المعروف)، واختُبر بمحاكاة fetch (`npm run verify`) وبمعالجة الأخطاء
  ضد الشبكة الحقيقية (نجحت بلا عطل)، لكن **لم يُختبَر مسار "عُثر على
  الكتاب فعلاً" حياً** لأي من الثلاثة بعد — نفّذ `npm run dev` وجرّب
  كتاباً تعرف أن Open Library لا يملكه (كتاب عربي حديث مثلاً) كخطوة
  تحقق أخيرة.
- **صور Wikidata**: قد تحتاج نطاق `upload.wikimedia.org` إضافة فعلية في
  `next.config.js` (أُضيف احتياطاً) إن كانت إعادة التوجيه من
  `commons.wikimedia.org` تسلك مساراً مختلفاً عملياً — تحقق بصرياً بعد أول
  كتاب يُجلَب عبر Wikidata.
